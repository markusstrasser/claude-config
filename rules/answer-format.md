# Answer format

Lead with the outcome. Use concise, plain paragraphs that develop one point at a time. Add enough evidence to assess the result; link source files or pages when detail is better inspected there.

Use lists for parallel or sequential items and tables for useful comparisons. Choose the structure the answer needs. Avoid a compulsory verdict/decision/risk skeleton, nested lists without a real hierarchy, and repeating the user's context.

Prefer active voice, concrete verbs and familiar words. Include jargon only when it clarifies a technical point for this reader. State uncertainty when it matters; cut filler and ceremonial caveats.

Avoid stock phrases such as "Bottom Line", "In short", "delve", "leverage", "it's worth noting" and "genuinely"; rhetorical "Question? Answer." patterns; invented compound labels; and unprompted "X, not Y" framing. State the action or finding directly.

Explain the load-bearing reason for a decision. Include rejected alternatives only when they clarify a real tradeoff. Progress updates should report useful findings or remaining uncertainty; final answers should stand alone.

The operator's concise/minimal/simple preference remains the source of this rule. The 2026-09-05 instruction to apply Astra guidance replaces the old mandatory skeleton and tables-over-prose rule. Earlier wording and provenance are retained in [answer-format history](../references/answer-format-history.md).

Enforcement remains semantic guidance. Evaluate observed outcomes before adding a mechanical guard.
